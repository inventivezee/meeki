---

## Fixes

- Importing recordings no longer runs while you are recording a call. Both used the same transcriber, and running them together could close the app mid-call and lose that recording. Starting a call now stops the file being transcribed and holds the rest of the import until the call ends. Nothing is lost — the interrupted recording stays in the queue
- Stopping an import now stops straight away, rather than finishing the recording already in progress first

- Summaries were being given up on before they could start. Transcribing frees the graphics memory the language model was using, so the summary that follows has to load the model again from scratch — and the wait for it was far too short. The summary was abandoned, the next recording started, and the model was unloaded again a moment later. One batch left 116 recordings with an empty summary against 13 that finished. The wait now allows for a cold start
- On a Mac with 32 GB of memory or more, the language model now stays loaded while a recording is transcribed, rather than being unloaded and read back from disk before every summary. Machines with less memory are unchanged, because holding both at once is what exhausts the graphics memory on those

## Improvements

- Settings → Recordings can now transcribe a batch without writing summaries. Summaries can be filled in afterwards in a single pass, which is quicker across a large import and leaves less to redo if it is interrupted
