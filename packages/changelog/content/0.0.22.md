## Recovering summaries

- **Process all**, in **Settings → Recordings**, now picks up recordings that were transcribed but never summarized — including any whose summaries failed during an earlier run. Previously a recording left that queue the moment its transcript was written, so a summary that failed afterwards could only be retried one note at a time
- A summary that started and produced nothing counts as missing, so a half-finished note is retried rather than treated as done

## Memory

- Transcription held on to graphics memory it had finished with — measured at 6.3 GB after a few hundred recordings, and most of the reason Meeki could be found sitting on 10 GB. It now keeps a fixed working amount and releases the rest
- That memory was also competing with the language model for the same limited pool, which is what caused the crashes during long transcription runs. This addresses the cause rather than the symptom
